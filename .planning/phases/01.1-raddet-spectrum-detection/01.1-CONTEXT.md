# Phase 1.1: RadDet Dataset Integration & Spectrum Sensing Benchmark (Limited Slice) - Context

**Gathered:** 2026-11-02  
**Status:** Ready for planning

<domain>
## Phase Boundary

Integrate the real-world **RadDet (ICASSP 2025)** radar spectrum detection dataset into the BTP testbench while strictly preserving all existing synthetic 77 GHz FMCW automotive radar simulation and deep learning pipelines.

For Phase 1.1, establish:

1. A minimal local footprint with a curated micro-slice (~50–100 frames, RadDet-9T-128) in `data/raddet_sample/` for rapid local offline testing and deterministic verification.
2. A clean, decoupled dataset loader and annotation visualizer in `src/raddet/`.
3. Deterministic unit tests in `tests/test_raddet.py` verifying YOLO-format bounding box normalization, multi-class mapping, and model forward pass.
4. A self-contained, publication-grade Kaggle notebook (`03_raddet_spectrum_detection_kaggle.ipynb`) that runs on Kaggle with `abcxyzi/raddet-icassp-2025` using a limited subset (e.g., 1,000–2,000 frames of RadDet-9T-128) to demonstrate fast convergence, compute `mAP50` and `mAP50:95`, and render visual detection figures (predicted bboxes with class and confidence scores vs ground truth).
5. Defer full-scale training (all 20,000 frames, 100 epochs, $256^2$ / $512^2$ resolutions, multi-SNR breakdowns) to **Phase 1.2**.

</domain>

<decisions>
## Implementation Decisions

### Dataset Selection & Local Footprint

- **D-01 (Target Dataset Variant):** Standardize on **RadDet-9T-128** ($128 \times 128$ max-hold spectrogram resolution, dense environment with up to 9 radar instances per frame) as the primary benchmark target for Phase 1.1. It presents the most challenging multi-target scenario while keeping file sizes minimal (~500 MB for the full split archive). — **Reversibility:** reversible.
- **D-02 (Local Micro-Slice):** Keep the local repository footprint ultra-lean. For local development, extract a curated micro-dataset (~50–100 spectrogram `.png` files and corresponding `.txt` label files) into `data/raddet_sample/` with a valid `data.yaml`. This ensures all deterministic local unit tests run in seconds without requiring downloading multi-gigabyte archives onto the local machine. — **Reversibility:** reversible.
- **D-03 (Automated Sample Fetcher/Extractor):** Provide a Python utility (`scripts/fetch_raddet_sample.py`) capable of either extracting sample frames from a downloaded Kaggle tarball or generating/downloading a tiny sample split for offline test verification. — **Reversibility:** reversible.

### Code Preservation & Architectural Decoupling

- **D-04 (Zero Disruption Invariant):** All existing synthetic radar files (`src/sim/*`, `src/dsp/*`, `src/models/radar_detector_cnn.py`, `01_radar_classical_dsp.ipynb`, `02_radar_deep_learning_detection.ipynb`) MUST remain untouched, fully functional, and green across all test gates. — **Reversibility:** one-way — Broken backwards compatibility violates the core project contract.
- **D-05 (Dedicated RadDet Module Namespace):** Create a dedicated new module package `src/raddet/` containing:
  - `src/raddet/dataset.py`: PyTorch/YOLO-compatible dataset reader, label parser, coordinate denormalizer, and train/val split utilities.
  - `src/raddet/visualize.py`: Spectrogram plotting utilities with bounding box overlays, class color palettes, and side-by-side Ground Truth vs Prediction figures matching Fig. 2 of the ICASSP 2025 paper.
  - `src/raddet/config.py`: Class dictionary (11 classes: Rect, Barker, Frank, P1, P2, P3, P4, Px, ZadoffChu, LFM, FMCW), color maps, and default hyperparameters. — **Reversibility:** reversible.

### Model Framework & Training Paradigm

- **D-06 (Ultralytics YOLO Architecture):** Adopt Ultralytics YOLO (YOLOv8n / YOLOv9-Compact) as the core detector engine for RadDet. Because RadDet annotations are provided in native YOLO format (`[class, x_center, y_center, w, h]`), using Ultralytics gives:
  - Direct out-of-the-box compatibility with `data.yaml`.
  - Native computation of `mAP50`, `mAP50:95`, precision, and recall matching the ICASSP paper's benchmarking standards.
  - High inference frame rate (exceeding 500+ FPS) suitable for real-time cognitive electronic warfare requirements. — **Reversibility:** reversible.
- **D-07 (Complementary Standalone PyTorch Smoke Test):** In `tests/test_raddet.py`, implement a lightweight PyTorch CNN forward pass test (using a simple CNN backbone or PyTorch layer) to guarantee that PyTorch-only environments can also ingest and pass gradients through the RadDet tensor representation without hard external CLI dependencies. — **Reversibility:** reversible.

### Kaggle Walkthrough & Execution Workflow

- **D-08 (Phase 1.1 Kaggle Notebook):** Generate a standalone, self-contained walkthrough notebook `03_raddet_spectrum_detection_kaggle.ipynb` configured to run directly in a Kaggle environment with GPU acceleration (P100 or T4 x2) attached to `abcxyzi/raddet-icassp-2025`.
- **D-09 (Limited Run Parameters for Phase 1.1):**
  - Dataset: Subset of RadDet-9T-128 (e.g. 1,000–2,000 train frames, 500 val frames).
  - Training: 10–20 epochs (fast completion within 10–15 minutes on Kaggle GPU).
  - Outputs: Loss curves, validation metrics (`mAP50`, `mAP50:95`), and a 4-panel visual comparison showing raw spectrograms, ground-truth bboxes, model predictions with confidence scores, and per-class precision-recall curves. — **Reversibility:** reversible.
- **D-10 (Phase 1.2 Roadmap Separation):** Phase 1.2 will handle the full 20,000-sample training run across $256^2$ and $512^2$ resolutions, 100 epochs, multi-SNR breakdown (-20 dB to +20 dB), and the full comparative benchmark table (YOLOv3, YOLOv6, YOLOv9, RT-DETR) from Table III of the paper. — **Reversibility:** reversible.

### Verification & CI Gates

- **D-11 (Deterministic Verification Gate):** Add `tests/test_raddet.py` to the test suite so that `pwsh -File ./scripts/verify.ps1` runs classical DSP tests, synthetic CNN tests, Kaggle integration tests, and RadDet loader/visualizer tests, maintaining 100% pass rate. — **Reversibility:** costly.

### Kaggle Platform Standards & Telemetry Invariants

- **D-12 (In-Container Telemetry Compliance):** Embed `StageProgressTracker` from `src.telemetry` into `03_raddet_spectrum_detection_kaggle.ipynb` to ensure automated stage-wise progress logging, throughput calculation, and real-time ETC/ETA projections without relying on external polling agents. — **Reversibility:** reversible.
- **D-13 (Dual-Path Resolution & Output Safety):** Enforce strict read-only handling of `/kaggle/input/` with automatic fallback to local `data/raddet_sample/`, and direct all model checkpoints, plots, and metrics to `/kaggle/working/`. — **Reversibility:** reversible.
- **D-14 (Automated Kernel Push CLI):** Provide `scripts/push_kaggle_kernel.py` to stage `kernel-metadata.json`, validate notebook syntax, and push directly to Kaggle via `kaggle kernels push`. — **Reversibility:** reversible.

### Coordinate Normalization Protocol

YOLO format format:
$x_{center} = \frac{x_{min} + x_{max}}{2 \cdot W}$, $y_{center} = \frac{y_{min} + y_{max}}{2 \cdot H}$, $w = \frac{x_{max} - x_{min}}{W}$, $h = \frac{y_{max} - y_{min}}{H}$
Inverse transformation:
$x_{min} = (x_{center} - w/2) \cdot W$, $y_{min} = (y_{center} - h/2) \cdot H$, $x_{max} = (x_{center} + w/2) \cdot W$, $y_{max} = (y_{center} + h/2) \cdot H$
