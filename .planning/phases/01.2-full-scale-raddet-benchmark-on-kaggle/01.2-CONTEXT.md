# Phase 1.2: Full-Scale RadDet Benchmark on Kaggle - Context

**Gathered:** 2026-11-02  
**Status:** Ready for planning  

<domain>
## Phase Boundary

Execute the full-scale 20,000-frame benchmark training and multi-SNR evaluation of RadDet on Kaggle GPU for the **S ($128^2$)** resolution variant (`RadDet-9T-128`), reproducing the baseline performance trends, Table III row, and multi-SNR metrics from the ICASSP 2025 conference paper (*"RadDet: A Wideband Dataset for Real-Time Radar Spectrum Detection"*).

To preserve compute budget and respect Kaggle GPU session timeouts, the resolution sweep is partitioned:
1. **Phase 1.2 (Active)**: Full 20,000-frame training and evaluation exclusively for **S ($128 \times 128$)** resolution for up to 100 epochs, automated multi-SNR evaluation across 6 SNR bins (-20 dB to +20 dB), and single-frame real-time CUDA-synced latency ($FPS_{avg}$) benchmarking.
2. **Phase 1.3 (Deferred)**: Full-scale RadDet benchmark for **M ($256 \times 256$)** resolution.
3. **Phase 1.4 (Deferred)**: Full-scale RadDet benchmark for **L ($512 \times 512$)** resolution.

</domain>

<decisions>
## Implementation Decisions

### Model Matrix & Backbone Selection

- **D-01 (Architecture Scope):** Standardize on **YOLOv9** (the paper's SOTA champion) alongside a **YOLOv8** comparative baseline natively supported in Ultralytics. Avoid unmaintained legacy repositories (YOLOv3 / YOLOv6) to keep the Kaggle container environment clean, reproducible, and robust. — **Reversibility:** reversible.
- **D-02 (Weight Initialization):** Initialize models using standard pretrained COCO weights (`yolov9c.pt` / `yolov8m.pt`) for accelerated feature convergence, numerical stability, and optimal training throughput within Kaggle GPU limits. — **Reversibility:** reversible.
- **D-03 (Model Scale Tier):** Focus exclusively on the **Medium/Compact tier** (`YOLOv9-M` / `YOLOv9-C` and `YOLOv8-M` with ~20M–25M parameters) directly corresponding to the primary parameter tier evaluated in Table III of the ICASSP paper. — **Reversibility:** reversible.
- **D-04 (RF Data Augmentation Protocol):** Replicate the paper's data augmentation suite in Ultralytics hyperparameters: Mosaic ($2 \times 2$, `mosaic=1.0`), Mixup (`mixup=0.2`), Copy-Paste (`copy_paste=0.2`), Translation (`translate=0.1`), Scaling (`scale=0.5`), with photographic HSV hue jitter strictly disabled (`hsv_h=0.0`) to preserve physical RF frequency-time integrity. — **Reversibility:** reversible.

### Resolution Sweep & Kaggle GPU Quota

- **D-05 (Single Resolution Scope for Phase 1.2):** Limit Phase 1.2 strictly to **S ($128^2$)** resolution across the complete 20,000-frame training set. Defer M ($256^2$) to Phase 1.3 and L ($512^2$) to Phase 1.4. This guarantees the run finishes in ~1.2–1.5 hours, safely avoiding Kaggle's 12-hour session timeout. — **Reversibility:** reversible.
- **D-06 (Epoch Budget & Safety):** Configure training for **100 epochs** (matching paper Section IV.A) equipped with an early-stopping safeguard (`patience=20`) to halt gracefully if validation loss plateaus, conserving weekly GPU quota. — **Reversibility:** reversible.
- **D-07 (Empirical Batch Size Smoke Test):** Implement an automated pre-flight benchmark test in the notebook evaluating batch sizes 32, 64, and 128 with Automatic Mixed Precision (`amp=True`) to dynamically select the maximum GPU throughput batch size before launching the 100-epoch training loop. — **Reversibility:** reversible.
- **D-08 (Periodic Checkpoints & Telemetry Throttling):** Save `best.pt`, `last.pt`, and periodic checkpoints every 10 epochs (`save_period=10`). Throttle standard console outputs and log structured stage metrics via `StageProgressTracker` to prevent Kaggle cell output buffer crashes (>20MB limit). — **Reversibility:** reversible.

### Multi-SNR Evaluation & Metric Reporting

- **D-09 (Automated Per-SNR Test Loop):** Evaluate the trained `best.pt` model across each of the 6 discrete SNR bins sampled in the test set: **-20 dB, -12 dB, -4 dB, +4 dB, +12 dB, and +20 dB**. Compute $mAP_{50}$ and $mAP_{50:95}$ per bin to plot the exact performance-vs-SNR curve matching Fig. 3(c). — **Reversibility:** reversible.
- **D-10 (Comprehensive Presentation Artifacts):** Generate both a markdown/CSV comparison table matching Table III of the ICASSP paper (reporting parameters, $mAP_{50}$, $mAP_{50:95}$, and $FPS_{avg}$) and an 11-class radar modulation breakdown chart. — **Reversibility:** reversible.
- **D-11 (Dedicated Real-Time Latency Benchmark):** Measure inference frame rate ($FPS_{avg}$) via a dedicated single-frame latency loop (batch size 1, CUDA event synchronization, 100 warmup frames, 1,000 timed test frames) to report unbiased real-time cognitive EW latency (ms) and FPS. — **Reversibility:** reversible.
- **D-12 (Multi-SNR Qualitative Grid):** Export a 4-panel visual diagnostic figure matching Fig. 1 and Fig. 2 displaying high SNR (+20 dB), moderate SNR (+4 dB), degraded low SNR (-20 dB), and overlapping waveforms with color-coded ground-truth vs predicted bounding boxes. — **Reversibility:** reversible.

### Kaggle Kernel Architecture & Artifact Packaging

- **D-13 (Unified Notebook Architecture):** Upgrade `03_raddet_spectrum_detection_kaggle.ipynb` in-place with an explicit mode switch: `FULL_BENCHMARK = True` vs `FULL_BENCHMARK = False`. This consolidates all RadDet Kaggle perception workflows into a single maintained notebook artifact. — **Reversibility:** reversible.
- **D-14 (Smart Cached Extraction):** Unpack `raddet40k128hw009tv2.tar` into `/kaggle/working/data/raddet_full_128/` with progress updates, automatically skipping decompression if dataset directories already exist. — **Reversibility:** reversible.
- **D-15 (Dual-Mode CI Verification):** In `tests/test_walkthrough_notebooks.py` and `tests/test_kaggle_integration.py`, execute a deterministic 1-epoch / 10-sample local smoke pass (<5s) when executed via `verify.ps1`, while full 100-epoch execution is activated on Kaggle GPU. — **Reversibility:** reversible.
- **D-16 (Dedicated Output Persistence & CLI Pull):** Store downloaded Kaggle benchmark artifacts in `data/benchmark_results/s128/` (preserving `data/kaggle_outputs/` for prototype runs). Enhance `scripts/push_kaggle_kernel.py` with `--pull` to download output files directly via Kaggle CLI. — **Reversibility:** reversible.

</decisions>
