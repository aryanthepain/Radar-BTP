# Phase 1.3: High-Coverage Deterministic Unit & Integration Testing - Context

**Gathered:** 2026-11-02  
**Status:** Ready for planning

<domain>
## Phase Boundary

Systematically expand deterministic unit, integration, and smoke test coverage across the repository to achieve **>=90% code coverage on `src/`** and comprehensive coverage of execution scripts (`scripts/`).

Baseline measurements show:
- Current overall `src/` coverage is **74%** (754 statements, 194 missed).
- Major coverage gaps:
  1. `src/models/radar_dataset.py` (19% coverage, 71 missed statements) — Synthetic dataset generator, bounding box math, heatmap encoding, and DataLoader batch collation.
  2. `src/dsp/aoa_estimation.py` (52% coverage, 27 missed statements) — MUSIC algorithm fallback paths, Capon MVDR estimator, pseudospectrum peak extraction.
  3. `src/dsp/clutter_removal.py` (57% coverage, 13 missed statements) — 3-pulse canceller vs 2-pulse canceller vs high-pass IIR clutter filtering.
  4. `src/dsp/doppler_processing.py` (56% coverage, 18 missed statements) — Windowing functions (Hanning, Hamming, Blackman), velocity axis computation, Doppler spectrum extraction.
  5. `src/dsp/cfar_detector.py` (63% coverage, 26 missed statements) — OS-CFAR vs CA-CFAR, edge guard cell checks, false alarm rate computations.
  6. `src/dsp/range_processing.py` (67% coverage, 9 missed statements) — Zero-padding scaling, windowing functions, range profile peak extraction.
  7. `src/raddet/` modules (85–89% coverage, 19 missed statements) — Edge cases in missing files, malformed labels, denormalization clamps.
  8. `scripts/` runners (`scripts/run_radar_pipeline.py`, `scripts/push_kaggle_kernel.py`) — Currently lack automated non-interactive CLI smoke tests.

All new tests must execute deterministically, run locally in under 30 seconds without network or GPU accelerators, and be integrated directly into the `scripts/verify.ps1` deterministic verification gate with `pytest-cov`.
</domain>

<decisions>
## Implementation Decisions

### Test Suite Organization & Modularity
- **D-01 (Dedicated Modular Test Suites):** Rather than bloating `tests/test_radar_dsp.py`, create distinct, single-responsibility test files:
  - `tests/test_dsp_edge_cases.py`: Focuses exclusively on algorithm branches, OS-CFAR, Capon/MUSIC AoA edge cases, MTI clutter filters, and Doppler windowing.
  - `tests/test_radar_dataset.py`: Comprehensive test suite for `RadarDataset`, DataLoader collation, multi-target bounding box coordinates, and heatmap encoding.
  - `tests/test_pipeline_scripts.py`: Non-interactive CLI smoke tests for pipeline runners, argument parsing, error exits, and kernel staging.
- **D-02 (Zero Disruption Invariant):** All existing 23 unit tests must continue to pass 100% without modification or regressions.

### Coverage Target & CI Integration
- **D-03 (Strict Coverage Gate):** Enforce `>=90%` overall statement coverage on `src/` via `pytest --cov=src --cov-report=term-missing`.
- **D-04 (Verify Script Enforcement):** Update `scripts/verify.ps1` to automatically run `pytest-cov` when available and report the coverage percentage.
- **D-05 (Sub-30s Execution Speed):** All test suites must use small synthetic radar configurations (e.g., $64 \times 32$ cubes or pre-computed synthetic tensors) so the complete suite executes in under 30 seconds on CPU.
</decisions>
